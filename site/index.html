devcontainer-mcp

Give Gemini, or any MCP client, a sandbox to run TypeScript in. One tool, inside a podman container you control, behind OAuth and an authenticator code.

Install

curl -fsSL https://devcontainer-mcp.vercel.app/install.sh | bash

Run it as a normal user. It asks before anything that needs sudo. Read the script first if you like. Linux (apt, dnf, zypper, pacman); macOS needs podman installed first.

What the installer does

  1. Installs podman if it is missing.
  2. Downloads the release binary for your system and checks its SHA-256.
  3. Creates your login: a generated password, an authenticator entry, and a client ID and secret.
  4. Builds and starts the sandbox container.
  5. Installs Tailscale if you want a public link without opening ports, shows the login link, and starts the server.

Connect Gemini

In the Google Cloud console: Gemini Enterprise, Data stores, Custom MCP Server, OAuth 2.0. Enter the values the server prints when it starts:

MCP server URLhttps://<your-link>/mcp
Authorization URLhttps://<your-link>/authorize
Token URLhttps://<your-link>/token
Client ID and secret~/.config/devcontainer-mcp/client.txt

Your link stays the same across restarts, so you set Gemini up once.

Security

  • Anyone with a valid login can run code in the container. The container is the blast radius: keep it free of anything you would not hand to the model.
  • Login is one password plus a time-based code. Five wrong attempts lock it for 15 minutes.
  • Tokens are tied to your link and stored only as hashes. Requests are rate limited. Every call is written to an audit log.
  • The container runs under rootless podman with memory, process and no-new-privileges limits.
